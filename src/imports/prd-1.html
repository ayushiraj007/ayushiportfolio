01 Overview

"Ask Ayushi" is a conversational AI agent embedded in Ayushi Raj's personal portfolio website. It is powered by Anthropic's Claude API and hosted on AWS Lambda via a Function URL, enabling visitors — recruiters, collaborators, or peers — to have a natural, first-person conversation with an AI that represents Ayushi's voice, background, and expertise.

This project is both a functional portfolio feature and a demonstration of applied AI product thinking — from system prompt engineering and context design to serverless deployment and frontend integration.
02 Problem Statement

A traditional portfolio website is static. It presents information but doesn't engage. Recruiters and visitors often have specific questions — about a particular project, a skill, or how Ayushi's background maps to a role — that a static page cannot answer efficiently.

Additionally, as someone actively exploring product management, strategy, and AI roles, Ayushi wanted her portfolio to itself be a demonstration of her ability to build and ship AI-powered products — not just describe that she can.

Core insight: A portfolio that lets you have a conversation is more memorable, more useful, and more authentic than one you just scroll through.

07 System Design & Architecture

The system follows a simple three-layer architecture: a static frontend widget, a serverless backend, and the Claude AI API.

Request flow: Visitor types message → Widget sends full conversation history as JSON → Lambda function receives POST request → Claude API generates response using system prompt → Lambda returns reply → Widget displays response

Key design decisions

  • Stateless backend: No database. Full conversation history is maintained client-side and passed on every request, keeping infrastructure minimal and cost near zero.
  • System prompt as knowledge base: All of Ayushi's background, personality, and rules are encoded in a structured system prompt. No RAG or vector search required at this scale.
  • Function URL over API Gateway: Eliminates an infrastructure layer, reduces latency, and simplifies CORS configuration for a single-origin use case.
  • API key as Lambda environment variable: Never hardcoded. Injected at runtime via Lambda's environment variable configuration.

09 Prompt Engineering Approach

The system prompt is the core product artifact of this project. It encodes Ayushi's identity, professional history, personality, values, and conversation rules — functioning as a structured knowledge base that the model reasons over at inference time.

Prompt structure:

  • Identity declaration — establishes first-person voice and prohibits generic AI framing
  • Current context — MBA status, internship goals, availability
  • Career history — structured by role with specific metrics and outcomes
  • Personal narrative — origin story, design philosophy, what drives her work
  • Interests and personality — hobbies, values, conversation style
  • Hard rules — contact info restrictions, confidentiality guardrails
  • Behavioral instructions — tone calibration, response length, how to handle unknown questions
Iterative prompt refinement was a core part of the build process — adjusting tone, adding depth on specific topics, and hardening guardrails based on test conversations.

Agent shares private contact details Low Hard rule in system prompt: only public email shared, phone and school email explicitly blocked
High unexpected traffic inflates API costs Low Lambda scales to zero when idle; can add AWS WAF rate limiting if needed
Model hallucinates incorrect career details Medium System prompt provides specific, verified facts with exact figures; model instructed to redirect to email if uncertain
CORS misconfiguration blocks widget Low CORS configured on Lambda Function URL with explicit allowed origin; tested with curl before launch
